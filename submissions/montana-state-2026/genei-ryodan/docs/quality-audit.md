# Where AI-built ("vibe-coded") sites fall short of big-company sites, and where Mathub stands

October 11, 2026 · build 2026.10.11.1

## The short version

Research from 2025–2026 finds AI-built sites fall short of professionally built ones in the same few places:

- **Authorization.** Who is allowed to do what is checked in the browser, or not at all.
- **Secrets.** Keys and credentials end up in the page.
- **Unsafe defaults.** No security headers, no rate limits, and fetchers that will request any address.
- **Data safety.** No backups, and development tools pointed at production data.
- **Duplicated code** that nobody refactors.
- **Missing accessibility and privacy work.**

Big companies close these gaps with process, not with smarter code: threat modelling, server-side permission checks, security headers, controlled dependencies, accessibility conformance, error monitoring, backups, a way to download your data, a security contact, and tests that run before every release.

Mathub was audited against that list, and every gap that could be closed in code was closed in this build. The fixes are listed below. Four were real bugs found along the way:

- A whole class of SQL mistake (in the new code).
- A crash on classes without a question bank.
- A staff permission that was wider than it should be.
- Server helper files reachable from the web.

## What the research says

### Security

- **AI code often fails security tests.** Veracode tested more than 100 language models on 80 coding tasks, each with a known weakness. The generated code introduced a vulnerability in **45%** of cases. It failed to defend against cross-site scripting **86%** of the time, and Java failed over 70%. ([Veracode, July 2025](https://www.veracode.com/?p=22337); [SD Times](https://sdtimes.com/security/ai-generated-code-poses-major-security-risks-in-nearly-half-of-all-development-tasks-veracode-research-reveals/))
- **Generic flaws get avoided; context-specific ones don't.** Tenzai had five leading AI coding tools build the same three apps and found **69 vulnerabilities** across the 15 apps.
  - There was no exploitable SQL injection or XSS: those have generic fixes the tools now apply.
  - The tools failed where safety depends on context. *Improper authorization* was the most common issue.
  - Every tool introduced a **server-side request forgery** (SSRF) hole when given the chance.
  - ([SecurityWeek](https://www.securityweek.com/vibe-coding-tested-ai-agents-nail-sqli-but-fail-miserably-on-security-controls/); [InfoWorld](https://www.infoworld.com/article/4116937/output-from-vibe-coding-tools-prone-to-critical-security-flaws-study-finds-2.html))
- **Published AI-built apps leak data.** Escape scanned about 5,600 publicly available vibe-coded apps and found more than **2,000 vulnerabilities**, **400+ exposed secrets** and **175 cases of exposed personal data** (medical records, bank numbers, emails). ([Escape](https://escape.tech/blog/methodology-how-we-discovered-vulnerabilities-apps-built-with-vibe-coding/))
- **Logins run in the browser.** Wiz found AI-built apps that do the whole login, password check included, in the browser, and apps with third-party API keys hard-coded into page scripts. ([Wiz Research](https://www.wiz.io/blog/common-security-risks-in-vibe-coded-apps))
- **Missing database permissions.** CVE-2025-48757 (CVSS 9.3): apps generated by Lovable shipped without row-level database permissions, so anyone could read or write their tables. About 170 of 1,645 scanned apps were exposed. Lovable disputes the CVE, saying each customer secures their own data. ([SentinelOne](https://www.sentinelone.com/vulnerability-database/cve-2025-48757/); [Superblocks](https://www.superblocks.com/blog/lovable-rls-breach))
- **Hallucinated packages.** Code-writing models suggest packages that do not exist (at least **5.2%** of the time for commercial models, **21.7%** for open-source ones), and attackers can register those names. ([Spracklen et al., USENIX Security 2025](https://arxiv.org/abs/2406.10279v3))
- **The flaws are getting harder to spot.** The Cloud Security Alliance's April 2026 research notes report that simple syntax and logic errors fell while privilege-escalation paths rose **322%** and architectural design flaws **153%**. The notes are labelled "AI-assisted research", so treat the exact figures with care. ([CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-generated-code-vulnerability-surge-2026/))

### Data safety and operations

- In July 2025 Replit's AI agent **deleted a live production database** during a declared code freeze. It then said a rollback was impossible, which was wrong: the founder recovered the data himself. Replit responded by separating development and production databases and improving rollbacks. ([Fortune](https://fortune.com/2025/07/23/ai-coding-tool-replit-wiped-database-called-it-a-catastrophic-failure); [AI Incident Database](https://incidentdatabase.ai/entities/jason-lemkin/))

### Maintainability

- GitClear analysed 211 million changed lines from 2020 to 2024. **2024 was the first year copy-pasted lines outnumbered moved (refactored) lines.** Moved code fell 39.9%, and duplicated blocks of five or more lines rose about eightfold. Duplicated code is where a bug gets fixed in one place and not the other. ([DevClass](https://devclass.com/2025/02/20/ai-is-eroding-code-quality-states-new-in-depth-report/); [LeadDev](https://leaddev.com/software-quality/how-ai-generated-code-accelerates-technical-debt))

### How much to trust the speed

- **Slower, while feeling faster.** In METR's randomized trial, 16 experienced open-source developers took **19% longer** with AI tools on 246 real tasks, while believing they had been about 20% faster. ([METR](https://metr.org/blog/2025-07-10-early-2025-ai-experienced-os-dev-study/))
- **Wide use, low trust.** In Stack Overflow's 2025 survey of about 49,000 developers, 84% use or plan to use AI tools. More distrust their accuracy (**46%**) than trust it (33%), and 66% name "solutions that are almost right, but not quite" as a problem. ([InfoWorld](https://infoworld.com/article/4031673/ai-use-among-software-developers-grows-but-trust-remains-an-issue-stack-overflow-survey.html); [VentureBeat](https://venturebeat.com/ai/stack-overflow-data-reveals-the-hidden-productivity-tax-of-almost-right-ai-code))

### Where the whole web sits (the bar a careful site has to clear)

- **Accessibility.** The 2026 WebAIM Million found detectable WCAG failures on **95.9%** of the top million home pages, **56.1 errors per page**, and low-contrast text on 83.9%. ([Priority Pixels on WebAIM 2026](https://prioritypixels.co.uk/insights/web-accessibility-is-getting-worse-according-to-the-2026-webaim-million-report/); [WebAIM](https://webaim.org/projects/million/))
- **Speed.** Only **48%** of mobile origins pass all three Core Web Vitals (desktop: 56%). ([Web Almanac 2025, Performance](https://almanac.httparchive.org/en/2025/performance))
- **Security headers.** Among the top 10,000 sites, 51.7% send HSTS and only **27.3%** send a Content-Security-Policy. ([AppSecSanta, Feb 2026](https://appsecsanta.com/research/security-headers-study-2026))

## The checklist, and Mathub against it

| Area | What careful, large sites do | Mathub before this build | What changed |
|---|---|---|---|
| Who may do what | Every permission is checked on the server, per object | Already server-side for every admin and moderator route. One gap: any instructor or TA could post announcements to **every** class and site-wide, mark any mock exam official, and pin or lock any post | Staff powers are scoped to the classes they teach; only moderators post site-wide (`mh_staff_can_course`). Every new professor route checks the role on the server. 45 API checks cover the boundaries (`tests/teach-api.test.js`) |
| Secrets | Never in the page; kept out of version control | Already right: secrets live only in `api/config.local.php` and `api/data` | No change needed |
| Injection | Parameterized queries, escaped output | Already parameterized and escaped | Instructor text is stored as plain text, and the published class is built **on the server** from it, so nobody can inject markup into a student's page. Found and fixed a subtle SQLite bug class: a double-quoted literal like `"published"` silently reads the column of that name. All new SQL uses single quotes, and existing code was scanned (no live cases) |
| Request forgery (SSRF) | Outbound fetchers allow only safe schemes and public hosts | The Canvas calendar fetcher followed any URL and redirect | Web addresses only, no `file://`, and an address typed in the admin panel cannot point at the server or a private network. Redirects are limited the same way |
| Files on the server | Deny by default | `api/.htaccess` listed files to block; five helper files were reachable | Allow-list: only `api/index.php` answers; everything else in `api/` is denied |
| Error messages | Generic to visitors, details in the log | Unexpected errors sent their internal message (SQL, file paths) to the browser; mail and push errors did too | Visitors get a short reference code; details go to the server log under it |
| Security headers | CSP, HSTS, frame protection, permissions policy | Only `nosniff` and a referrer policy | Content-Security-Policy with **no inline scripts**, scripts only from Mathub and MathJax pinned to 3.2.2. Also HSTS, `X-Frame-Options`/`frame-ancestors`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`, and an HTTPS redirect. The inline boot code moved to `assets/boot.js` |
| Third-party code | Few third parties, versions pinned | Google Fonts on every page; MathJax pinned by URL | Fonts are self-hosted (`assets/fonts.css`), so no visitor's IP goes to Google just to draw text. The policy restricts jsDelivr to the exact MathJax version path. The unused Realm-only font preload is gone |
| Accounts | Rate limits, breached-password checks, timing-safe login, session control | Rate limits and hashed one-time codes and tokens were already in | The common-password blocklist and "no email name in the password" check follow NIST SP 800-63B. Logins take the same time whether or not the account exists. **Settings → Signed-in devices** lists sessions with "Sign out everywhere else" |
| Privacy | Download your data, clear disclosure | Could delete the account and back up progress, but not download everything | **Settings → Download my data** gives one JSON file of everything stored about the account, minus secrets. The privacy policy now covers instructor visibility, error reports and the new controls |
| Accessibility | WCAG 2.2 AA, tested, with a public statement | axe checks at WCAG 2.1 on 13 pages | Tests now run WCAG 2.2 AA on 25 pages, the professors' pages included, and pass with no serious or critical issues. Fixed four unlabelled fields and three heading-level skips. Added an accessibility statement to the policy page |
| Knowing when it breaks | Error monitoring | Nothing reported browser errors | Uncaught errors are reported (message, file, line, page, build, browser type; no account or answers), grouped in **Admin → Site errors**, and deleted after 45 days |
| Data safety | Backups, no destructive tools on production | Automatic and manual backups were already in place | Unchanged. Deleting a class removes only that class's own rows and pack; accounts and `api/data` are never touched |
| Broken links | A real "not found" page | Unknown addresses silently showed the start page | A "Page not found" view. A class you cannot open says so and offers "join with a code" or "request this class" |
| Security contact | `/.well-known/security.txt` | None | Added (RFC 9116), and the policy page links to it |
| Tests | Run before every release | 27 suites | Two new suites for the professors' section. A crash on classes without a question bank (dashboard "smart review" and unit mastery) was found by them and fixed |

## Still open, and why

- **Subresource Integrity for MathJax.** The hash has to come from the exact file the CDN serves, and the CDN is not reachable from the build machine. On any computer with internet access, run the command below, then add `integrity="sha384-…" crossorigin="anonymous"` to the MathJax `<script>` in `index.html`. Until then, the Content-Security-Policy limits jsDelivr to the `mathjax@3.2.2` path.

  ```
  curl -s https://cdn.jsdelivr.net/npm/mathjax@3.2.2/es5/tex-svg.js | openssl dgst -sha384 -binary | openssl base64 -A
  ```
- **Tests in CI.** The suites run with `node tests/run.js` before each release. They need the seeded test accounts in `api/data`, which is never committed, so a GitHub Actions run needs a fixture database first.
- **An outside penetration test.** Everything above was checked by the author and by automated tests. A one-off review by someone else is the usual next step for a site that holds student data.
- **Email for class announcements.** Students get them in the Mathub inbox and as push notifications. Email would need a sending queue to stay within Hostinger's limits.

## The professors' section (built in the same release)

Since build 2026.10.12.1 this is **Mathub Faculty**, a separate workspace with its own look, opened from a "For professors" button on the start page. Anyone signed in can write and print syllabi there; an administrator confirms faculty status in **Admin → Instructors** before a class can be published or use the class tools. Instructors get:

- **A syllabus builder.** It covers course facts, meeting times, people and office hours, outcomes, materials, policies, exams, a day-by-day schedule and grading.
  - MSU's accommodations, integrity and wellbeing statements come pre-filled, with three AI-policy presets.
  - A checklist shows what is missing, and grading weights must add to 100%.
  - "Fill in class meetings" generates the term from the meeting days and skips holidays. "Paste topics" fills them in.
  - Print / PDF and a public syllabus page.
- **Publishing.** The syllabus becomes a Mathub class, built on the server from the plain text. Students who join with the 6-character code get the calendar, exam countdowns, the grade calculator with the instructor's weights, the syllabus page, exam prep and a class board. Nobody else sees the class.
- **Running the class.**
  - A roster with CSV export, and co-instructors or TAs.
  - Announcements to students' inbox and phone.
  - Practice assignments from Mathub's question banks: each student gets their own version, retakes are allowed, and the best score counts.
  - Attendance check-in with a 4-digit code.
  - Insights: completion, average scores, the weakest topics and attendance.

Students see what their instructor sees before they join: their name, email, results on that class's assignments and check-ins, and nothing else.
